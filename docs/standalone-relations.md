# Связи самостоятельных публикаций — Phase 7.6.4

`StandaloneRelationService` связывает самостоятельное уточнение, исправление или отмену с более ранней публикацией. Предложение хранится отдельно в `standalone_relation_candidates`; неподтверждённые предложения не добавляются в RAG как факты.

## Отбор и подтверждение

1. Backend рассматривает не более 100 предыдущих текстовых сообщений **того же канала** за 120 дней до исходного сообщения. Порядок проверяется и по Telegram message ID, и по дате публикации.
2. Используются пересечение заголовков/текста, компания, тип metadata и косинусная близость уже сохранённых векторов. Metadata и векторы с устаревшим содержимым исключаются. Новые embedding API вызовы при отборе не выполняются.
3. Кандидат приводится к корневой публикации существующей цепочки. Циклические и неоднозначные цепочки пропускаются. В очередь попадают максимум три корня.
4. LLM сравнивает только конкретную пару, выбранную backend. Несовпадающий source/target ID, некорректная схема JSON и уверенность вне 0–1 считаются ошибкой, а не основанием для создания связи.
5. Автоматическое подтверждение требует единственного сильного кандидата либо отрыва не менее 0,20 от второго кандидата, явного маркера изменения, уверенности модели не ниже 0,98 и типа UPDATE/CORRECTION/CANCELLATION. Одной семантической близости недостаточно. MIXED и сомнительные случаи идут в REVIEW_REQUIRED.
6. Повторяющиеся вакансии одной компании и похожие мероприятия сами по себе связью не считаются. Точечная отмена описывается как отмена конкретной части; остальные условия сохраняются.

Подтверждённая автоматически связь получает `STANDALONE_INFERRED`. Подтверждение менеджера получает `ADMIN_CONFIRMED`. Наличие любой существующей связи у source запрещает автоматическое создание ещё одной; MANUAL, ADMIN_CONFIRMED, TELEGRAM_REPLY и SYSTEM_BACKFILL не перезаписываются.

## Редактирование и надёжность

- SHA-256 входных текстов, идентификаторов, дат и версии классификатора предотвращает повторные вызовы для неизменной пары.
- При изменении source/target неподтверждённые и автоматические результаты устаревают. Удаляется только автоматическая связь с тем же input hash; ручные решения остаются в силе. Создаётся новое предложение для изменившегося содержимого.
- Claim и сохранение результата выполняются короткими отдельными транзакциями; сетевой вызов находится между ними. Изменившийся во время вызова текст не может получить результат старой классификации.
- Решения одного source сериализуются блокировкой строки. Повторная проверка существующей связи выполняется перед применением результата.
- Максимум три попытки для одного input hash. Автоматический повтор — через 5 и 10 минут; ручной retry не сбрасывает счётчик. После исчерпания менеджер может принять решение вручную.
- Зависшая более 10 минут попытка переводится в FAILED с сохранением счётчика. Сохраняются снимки исходных текстов, события аудита, автор ручного решения, provider/model и каждый сырой ответ классификатора. Тексты и ответы не печатаются в информационные логи.

## Интеграция

`StandaloneRelationBackgroundWorker` реагирует на сохранение поста и успешную индексацию. Каждые 10 минут он проверяет последние 100 постов и обрабатывает до 10 готовых кандидатов. Первое фоновое выполнение — через 60 секунд. Дедупликация сохраняется между перезапусками в БД.

Настройки (значения по умолчанию):

```properties
careerai.background.enabled=true
channel-post-relations.standalone-enabled=true
channel-post-relations.standalone-reconcile-ms=600000
channel-post-relations.standalone-initial-delay-ms=60000
```

Любой из первых двух флагов `false` отключает listeners и scheduler. Административные методы при этом доступны через защищённую админку.

Сервисные операции: `discover(postId)`, `process(candidateId)`, `processPending(limit)`, `list(status,page,size)`, `approve(id,type,reason,actor)`, `reject(id,reason,actor)`, `retry(id,actor)`, `audit(id)`. Вызовы `process` и `processPending` должны поступать без внешней транзакции. Retry ставит предложение в очередь, а не выполняет сетевой вызов немедленно.

`StandaloneRelationCandidateRepository.hasUnresolvedForPostIds(ids)` позволяет быстрому режиму ответа отказаться от прямой выдачи при незавершённой классификации. Он покрывает уже обнаруженные предложения; перед обнаружением связей по косвенным признакам гарантии автоматического распознавания нет.

## Проверка на тестовых данных

Проверить пару «анонс мероприятия → самостоятельная отмена той же встречи», похожее независимое мероприятие, повтор вакансии той же компании, изменение дедлайна, частичную отмену, отредактированную отмену, цепочку reply → standalone, межканальные сообщения и ошибку AI-провайдера. Перед демонстрацией менеджерам стоит просмотреть REVIEW_REQUIRED и FAILED: модельная уверенность сама по себе не является гарантией правильной связи.

Миграция V13 добавляет только новые таблицы и допустимое происхождение связи. При возврате к старой версии приложения новые связи с `STANDALONE_INFERRED` необходимо предварительно экспортировать и удалить либо преобразовать согласованной миграцией: старая Java enum не умеет читать это значение. Простого переключения Git-ветки для отката базы недостаточно.
