# Выбор модели Groq и резервный Gemini

Основной провайдер приложения по умолчанию — Gemini. Анализ вопроса использует отдельную стратегию `GROQ_FIRST`: сначала Groq, затем Gemini при ошибке. Поэтому `LLM_PROVIDER=GEMINI` само по себе не отключает Groq для анализа вопроса.

По [официальному объявлению Groq](https://console.groq.com/docs/deprecations), `llama-3.1-8b-instant` отключена для free/developer-доступа 16 августа 2026 года. Рекомендуемая замена — `openai/gpt-oss-20b`. Enterprise-контракты оговорены провайдером отдельно.

В проекте используется:

```text
GROQ_API_MODEL=openai/gpt-oss-20b
```

Это значение по умолчанию; явно задавать его в IntelliJ не обязательно. Если переменная уже существует со старым названием модели, обновить её. Запросы идут в Groq с существующим `GROQ_API_KEY`; модель Gemini остаётся прежней. Доступные модели можно проверить через авторизованный `GET https://api.groq.com/openai/v1/models`. Наличие в каталоге не заменяет проверку конкретного запроса и ограничений аккаунта.

Для точных ID `openai/gpt-oss-20b` и `openai/gpt-oss-120b` адаптер задаёт `reasoning_effort=low`, `include_reasoning=false` и `max_completion_tokens`. К бюджету задачи добавлены 1024 токена для reasoning, общий лимит ограничен 65536. Это верхняя граница, а не количество токенов, обязательно расходуемых на каждый запрос. Для других моделей сохранены прежние параметры. [Документация Groq о reasoning](https://console.groq.com/docs/reasoning).

JSON-режим сохраняется для анализа вопроса. Адаптер возвращает только `message.content`; незавершённый ответ с `finish_reason=length` считается ошибкой и может уйти на резервного провайдера. Ошибка `model_not_found` выводится кратко с подсказкой проверить `GROQ_API_MODEL`, без большого стека. Прочие HTTP 404 не объявляются ошибкой модели без соответствующего кода в ответе провайдера.

`DIRECT_ANSWER` для приветствия сейчас означает пропуск второго вызова генерации и embeddings. Первый вызов анализатора остаётся, если вопрос ещё не находится в кэше. Время отдельного запроса к модели не равно полному времени ответа в Telegram: дополнительно учитываются очередь, работа приложения и доставка.

После изменения модели нужно перезапустить `BackendApplication`. Окно HTTPS-туннеля и PostgreSQL перезапускать не требуется.
