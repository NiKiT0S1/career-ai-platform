## Особенности локального окружения

Ограниченная Windows-сессия не позволяла javac разрешить родительские каталоги при закрытии ZIP classpath. Использован временный внешний адаптер настоящего javac 21: он сохранял ошибки/exit code, снимал directory classpath в JAR и обходил только ошибку закрытия ZIP после успешной компиляции. Адаптер проверен на заведомо ошибочном Java-коде. Параметры проекта и production-сборки не менялись ради этого обхода. Для Java NIO задан короткий временный каталог Unix-domain sockets. Эти локальные файлы не входят в репозиторий.

CI выполняет обычный Maven verify на Linux/Java 21 с отдельным PostgreSQL 17, без Windows-адаптера. Результат каждого удалённого запуска следует проверять в GitHub Actions.

## Что ещё требует внешнего подключения

- Публичный HTTPS-адрес и ID администраторов задаются в локальной конфигурации и не входят
  в репозиторий. Новый вход через кнопку меню нужно открыть в Telegram после перезапуска.
- Новый код не запускался вторым polling-ботом на рабочем токене. Полный повтор вопросов
  через настоящий Telegram и индекс рабочего канала остаётся пользовательской приёмкой.
  Настоящие Gemini/Groq проверены на синтетическом наборе, описанном выше.
- Нет обещания конкретного времени ответа AI. Тесты подтверждают сокращение вызовов на быстрых путях и корректность fallback; фактическая задержка зависит от провайдера.
- Запуск на постоянном сервере не выполнялся. Подготовка и переключение описаны в docs/deployment.md.
