# Панель администратора CareerAI

Панель предназначена для сотрудников ЦКиТа: проверять знания бота, исправлять структуру объявлений, управлять FAQ и разбирать связи публикаций. Она открывается как Telegram Mini App из личного чата с ботом. Вход через обычную ссылку без Telegram-авторизации не даёт доступа к данным.

## Первое подключение

1. Запустить новую версию backend на отдельной базе, как описано в [deployment.md](deployment.md).
2. Разместить приложение за публичным HTTPS-адресом с действующим сертификатом. Панель находится по пути `/admin/`, её API — `/api/admin/` на том же домене.
3. Каждый сотрудник пишет боту `/myid` в личном чате. Нужен числовой **ID пользователя**, а не username, ID группы или ID канала.
4. Настроить окружение сервера:

```text
ADMIN_ENABLED=true
ADMIN_TELEGRAM_USER_IDS=123456789,987654321
ADMIN_PUBLIC_URL=https://career.example.org/admin/
```

Числа и домен выше — примеры; заменить их реальными значениями. При изменении переменных перезапустить приложение. По умолчанию `ADMIN_ENABLED=false`, список пользователей и адрес пусты.

5. Разрешённый сотрудник пишет `/admin` в личном чате и нажимает «Открыть панель».

Команда в группе предлагает перейти в личный чат. Пользователь вне списка не получает кнопку. При отсутствии HTTPS-адреса бот сообщает, что настройка не завершена. Сервер повторно проверяет подпись Telegram `initData`, срок действия и ID администратора при каждом запросе API; сама кнопка не заменяет эту проверку. Bot token и ключи AI не передаются браузеру.

Срок авторизационных данных по умолчанию — один час (`careerai.admin.auth-max-age-seconds=3600`). При сообщении о повторном входе закрыть панель и снова открыть её через `/admin`.

## Разделы

### Публикации

Поиск по тексту, категории, статусу и дате публикации. Можно открыть исходный текст, посмотреть извлечённые сведения и причину текущего статуса.

- **Архивировать** — убрать публикацию из обычных и исторических ответов студентам, сохранив её в базе.
- **Восстановить** — снять ручной архив. Истёкший срок остаётся истёкшим; восстановление не делает старую вакансию действующей.
- **Пересчитать актуальность** — проверить дату и срок по имеющейся структуре.
- **Изменить сведения** — исправить категорию, название, компанию, технологии, формат, сроки, описание и связь с практикой. Причина исправления попадает в аудит.
- **Повторно извлечь сведения** — поставить metadata на повторную обработку.
- **Переиндексировать** и **найти связанные публикации** — запустить соответствующую операцию обслуживания.

Исправление metadata в панели не редактирует исходный Telegram-пост. Если неверна сама публикация в канале, исправить её в Telegram; бот обработает поступившее обновление отдельно.

### База знаний

Создание и редактирование FAQ: категория, уникальный slug, вопрос, краткий ответ для `/faq`, полный ответ, ключевые слова, приоритет и активность. Неактивный FAQ исключается из обычной базы ответов. Проверенные полные ответы могут выдаваться без дополнительной генерации при точном совпадении вопроса.

FAQ — источник официальных правил, поэтому указанные здесь контакты, документы и процедуры должны соответствовать правилам центра. Перевод/переформулировка при неточном совпадении остаётся задачей RAG.

### Связи публикаций

Управление подтверждёнными связями: дополнение, исправление, отмена или смешанное изменение. Доступны ручное связывание, подтверждение/исправление типа и причины, удаление ошибочной связи и повторная классификация поддерживаемых reply-связей.

При частичной отмене указать конкретное отменённое условие: например, «раздача подарков отменена». Не заменять это на «мероприятие отменено», если объявление не отменяет событие целиком.

### На проверку

Кандидаты связей самостоятельных публикаций хранятся отдельно. Проверить исходную и предполагаемую основную публикацию, тип изменения, объяснение, уверенность и ошибки. Можно подтвердить связь с собственным объяснением, отклонить или запросить допустимый повтор. Сомнительный кандидат не становится подтверждённой связью автоматически.

Ручные решения имеют приоритет перед автоматикой. Подробнее о порогах, повторных попытках и сохранении решений — в [standalone-relations.md](standalone-relations.md).

### Обслуживание

Пакетная сверка embeddings и обработка кандидатов, а также статусы административных заданий. Повтор одной уже запущенной операции отклоняется; переполненная очередь предлагает повторить позже. Переиндексация и AI-классификация могут обращаться к внешним API и расходовать их квоты.

Очередь административных заданий находится в памяти: один worker, до 20 ожидающих задач, до 200 записей статуса на сутки. После перезапуска отображаемые статусы исчезают; постоянные данные, retry-state и аудит остаются в PostgreSQL. Для остановившейся операции проверить состояние записи перед повтором.

### Журнал действий

Показывает администратора, действие, объект, время и сохранённое объяснение. Кандидаты дополнительно имеют собственную историю решений. Журнал не является полным дампом базы и не заменяет резервное копирование.

## Одновременные правки

Публикации, metadata, FAQ и связи имеют версии. Если другой сотрудник уже изменил запись, устаревшая форма не должна перезаписать его работу: обновить карточку и повторить нужное изменение по новой версии.

## Перед демонстрацией

Проверить вход разрешённого сотрудника и отказ постороннему; открыть панель на телефоне и на компьютере; изменить тестовый FAQ; архивировать и восстановить тестовую публикацию; подтвердить и отклонить разные кандидаты; убедиться, что действия отражаются в журнале и ответы студента учитывают изменения. Использовать отдельные тестовые записи и копию базы.

Если внешний HTTPS-адрес ещё не настроен, backend и локальные проверки можно запустить отдельно с `TELEGRAM_POLLING_ENABLED=false`. Наличие локальной страницы само по себе не проверяет реальный запуск Mini App внутри Telegram.
